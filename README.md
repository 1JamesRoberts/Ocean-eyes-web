# OceanEyes Flutter

OceanEyes is a production-first Flutter aquarium-monitoring client for
Android, iOS, and web. It includes tank pairing, Firebase-backed state, camera
monitoring, on-device fish/water inference, alerts, and LiveKit streaming.

## Run

Firebase application options are generated by FlutterFire and stored in
`lib/firebase_options.dart`. Regenerate that file when the Firebase project or
platform registrations change:

```powershell
flutterfire configure --project ocean-eyes-webapp
```

Run the credential-free local preview during UI development:

```powershell
flutter pub get
flutter run
```

Debug and profile runs use the local preview by default. The VS Code Run/Debug
menu includes the same `OceanEyes (local preview)` configuration.

Copy `config/production.example.json` to a secure location outside the
repository and replace its placeholders. The file contains only OAuth, web
messaging/App Check, Functions, and legal-link values; Firebase application
options come from `lib/firebase_options.dart`.

Run the production app with the same command used for a release build:

```powershell
flutter pub get
flutter run -d edge --dart-define-from-file=C:\secure\oceaneyes-production.json
```

Build artifacts directly with Flutter:

```powershell
flutter build web --release --dart-define-from-file=C:\secure\oceaneyes-production.json
flutter build appbundle --release --dart-define-from-file=C:\secure\oceaneyes-production.json
flutter build ipa --release --dart-define-from-file=C:\secure\oceaneyes-production.json
```

Android release builds require the untracked `android/key.properties` and its
approved keystore. The app does not have a fixture/emulator runtime; tests use
injected fakes and deterministic data without starting Firebase.

Common validation commands:

```powershell
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
npm --prefix functions test
```

## Architecture

```text
lib/
  app/           production bootstrap, configuration, and navigation
  core/theme/    shared visual tokens and theme
  models/        domain entities, repositories, and pure services
  integrations/  Firebase, camera, ML, LiveKit, and wake-lock gateways
  view_models/   controller state and responsibility-focused coordinators
  ui/            screens, shell layout, widgets, and rendering
```

`OceanEyesController` is the state API consumed by screens. Coordinators keep
navigation, persistence, onboarding, Firebase bindings, camera/ML, LiveKit,
and wake-lock lifecycles out of widgets. Models contain no Flutter UI code.

## Production boundary

Release builds always start through the Firebase/auth/Firestore production
composition root. Firebase options are generated once by FlutterFire; runtime
defines are limited to the values that cannot be represented there. App Check
uses the production provider on Android, iOS, and web. Missing production
configuration stops startup with an actionable error instead of silently
showing demo data. Debug/profile local preview runs deliberately skip Firebase
composition and do not require production credentials.

The production validation record is in
[`docs/production_validation.md`](docs/production_validation.md). Backend
deployment uses [`firebase.json`](firebase.json) and the Functions package.

## Visual validation

The visual harness still uses deterministic controller doubles so UI snapshots
remain stable without network or hardware. See
[`docs/visual_validation.md`](docs/visual_validation.md) and
[`docs/visual_tokens.md`](docs/visual_tokens.md).
